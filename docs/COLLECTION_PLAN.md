# 真实样本采集方案

更新日期：2026-10-22。

## 为什么需要样本

当前所有换算参数都是启发式设定的：题目区分度全部为 1.0，难度阈值按题目内容猜测，
合成分斜率借用自韦氏官方示例报告。合成被试自检显示，按当前参数，
模型定义的平均能力（θ=0）对应题库整体预期得分率 82.5%——远高于韦氏常模中位数（约 50%），
意味着多数真实用户会被系统性判为低于平均。

要修掉这一点，只有一条路：拿到真实作答数据。

## 分阶段

| 阶段 | 人数 | 目的 | 产出 |
| --- | --- | --- | --- |
| 试采集 | 20–30 | 验证采集流程、导出格式、数据质量门槛 | 一份数据质量报告，确认流程可跑通 |
| 中规模 | 150–250 | 重新标定斜率、估计可靠性相关 | 校准后的斜率，区间宽度收窄到可信范围 |
| 正式采集 | 500+ | 拟合题目参数、检验维度结构 | 参数拟合结果，四指数结构是否成立的证据 |

**不要跳过试采集。** 中规模和正式采集的样本若存在系统性问题（例如被试集中在同一水平段、
超时比例过高），在几百人之后才发现的代价远高于先跑 20 人。

## 招募：能力水平必须覆盖全谱

这是最容易被忽略、也最致命的一点。

斜率标定的本质是测量「真实能力分布的离散度」，然后让合成分的标准差等于 15。
**如果被试的能力都集中在某个窄区间，测出的离散度就偏小，标定出的斜率就偏大**，
结果是把一个更窄的分布放大成标准差 15，等于制造了虚假的区分度。

因此招募时必须覆盖不同水平，至少考虑：
- 青少年与成人（16 岁是韦氏常模的分界；本项目未做年龄校准，但年龄跨度会扩大能力分布）
- 不同教育背景
- 自评能力明显不同的群体

不需要（也无法）随机抽样。**目标是覆盖范围，不是代表总体。**

## 知情同意与隐私

这一节不能省。逐题作答数据是行为数据，比问卷更敏感。

必须让被试知道并同意：
- **收集什么**：每道题的作答、正确与否、用时、开始时的年龄、题组、完成状态
- **不收集什么**：姓名、账号、设备标识——应用本身不采集这些，导出文件里也没有
- **用途**：仅用于本项目的题目参数标定与换算校准
- **是否公开**：分析结果可公开，**原始逐题数据不公开**
- **能否退出**：随时可删除；退出后请一并删除其导出文件

实务建议：把导出文件集中到一个目录，同意书与文件一一对应；被试要求退出时删掉对应文件即可，
不必重做分析。

## 操作流程

1. 被试在应用首页填入年龄（可选，但强烈建议填——缺年龄就无法检查年龄效应）
2. 选择题组。**A/B 两组目前参数照抄、尚未等值**，混合采样会污染分析；
   建议一轮采集固定用一个题组，并在报告里注明用的是哪组
3. 完成完整练习（120 题）。中途退出的记录不会进入标定——脚本会自动排除
4. 完整练习结束后在结果页点「导出 JSON」；也可在历史页批量导出
5. 把所有人的导出文件放进同一个目录

## 数据检查与合并

```bash
python3 docs/calibration_export.py <导出文件目录> -o calib_out
```

脚本会合并多个文件（记录以 UUID 标识，重复 ID 会被检出并报告），产出：

| 表 | 用途 |
| --- | --- |
| `items.csv` | 题目参数与归属，作拟合初值 |
| `responses.csv` | 逐被试逐题得分，标定的主输入 |
| `persons.csv` | 被试元信息与作答完整度，用于筛选 |
| `baselines.csv` | 各分测验的难度基准 |
| `quality.txt` | **先读这个**：缺失、超时、中断、重复 ID、年龄覆盖 |

`quality.txt` 里有一条硬门槛：有超时或中断的记录会被标出。
这些项目不是「做错」而是「没做完」，混进离散度估计会把分布压窄。
`calibrate_slopes.py` 因此只接受完整作答的记录。

## 分析计划

1. **先标定斜率**：
   ```bash
   python3 docs/calibrate_slopes.py calib_out
   ```
   它复用自检的同一套估计流程但换成真实作答，实测尺度分之和的离散度，
   反推「让合成分标准差回到 15」的斜率。参考值见
   [WECHSLER_STYLE_SCORING.md](WECHSLER_STYLE_SCORING.md) 的「标定状态与已知偏差」。

2. **再做参数拟合**。斜率标定只是把刻度摆正；题目参数本身（区分度全为 1.0、阈值靠猜）
   仍然未经检验。拟合用 `items.csv` 的阈值作初值、`responses.csv` 的得分作观测。

3. **拟合完成后重跑诊断**：
   ```bash
   python3 docs/run_diagnostics.py --update   # 重建基线
   python3 docs/run_all.py                    # 全部诊断
   ```
   数字应向合理方向移动：合成分标准差接近 15、各分测验难度更齐、可靠度相关上升。

4. **只有拿到配对的正式测验分数，才能谈效度**。若被试恰好有合适的正式测验成绩
   （记录版本、语言、施测日期），才可能做相关分析——那才是「这套题能不能预测韦氏」的答案。
   没有配对数据时，任何效度声明都没有依据。

## 明确不做的事

- 不把互联网自选样本当作总体常模
- 不用本项目自己的分数「验证」自己的分数
- 不在参数拟合前就宣称结果已校准
- 不公开原始逐题数据
- 不把「拟合后离散度变好看」当作效度证据——离散度只是刻度，不是正确性
